# Відповіді на контрольні питання №10

1. **HTTP і WebSocket.** У звичайному HTTP клієнт надсилає запит і отримує відповідь. WebSocket підтримує постійне двостороннє з’єднання: сервер може надсилати події без нового запиту клієнта.
2. **Socket.IO.** Додає іменовані події, автоматичне перепідключення, підтвердження отримання, кімнати та резервний HTTP long-polling. Це власний протокол поверх транспортів; чистий WebSocket-клієнт не замінює socket.io-client.
3. **Broadcasting.** `server.emit()` надсилає подію всім, включно з відправником. `client.broadcast.emit()` - усім, крім нього. `client.emit()` - лише одному клієнту.
4. **Кімнати.** Сервер групує сокети за іменем кімнати; `server.to(room).emit()` адресує учасникам цієї групи. Сервер контролює членство, щоб у реальній системі перевіряти права. У навчальній роботі дозволені кімнати формату `drop_<id>`.
5. **SSE.** Односторонній довготривалий HTTP-потік від сервера до браузера. Підходить для метрик, статусів і новин, коли двосторонній обмін не потрібен. Браузер використовує EventSource.
6. **Формат SSE.** UTF-8 рядки `data: ...`, необов’язкові `id: ...`, `event: ...`, `retry: ...`; порожній рядок завершує подію. `id` допомагає відновленню, `event` задає тип, `retry` - затримку перепідключення в мілісекундах.
7. **RxJS Observable.** Описує потік значень у часі. `interval(5000)` генерує значення кожні 5 секунд, `map()` перетворює їх на MessageEvent. Після розриву SSE NestJS відписується від потоку.
8. **SMTP-пастка.** Mailpit приймає листи й показує їх локально, не доставляючи реальним адресатам. Це дозволяє перевірити HTML, тему й одержувача без випадкових листів користувачам; корисна стандартна практика розробки, а не вимога самого SMTP.
9. **WebSocket + Email.** WebSocket одразу оновлює активну вкладку; лист зберігається в поштовій скриньці й доступний пізніше. У цій роботі обидва канали повідомляють про початок продажів колекції.
